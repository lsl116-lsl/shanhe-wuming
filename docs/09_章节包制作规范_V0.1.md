# 《山河无名》章节包制作规范 V0.1

> 文档状态：全章节内容生产规范
>
> 上位规范：`docs/00_项目总框架_V0.4.md`
>
> 用途：规定每章文件结构、人物深度、职业独立主线、分场剧本、因果状态与跨章汇流方式。

## 1. 标准章节目录

```text
docs/chapters/
  CHXX_章节名/
    00_章节定位与史实边界_V0.1.md
    01_主线大纲_V0.1.md
    02_人物关系表_V0.1.md
    03_职业线嵌入表_V0.1.md
    04_因果节点表_V0.1.md
    05_记忆碎片表_V0.1.md
    06_故事剧本_V0.1.md
    07_至下一章衔接过渡文_V0.1.md
```

终章可以取消职业分流和“至下一章”文件，但必须拥有全局回收表与完整剧本。

## 2. 八份文件分别解决什么

| 文件 | 只负责回答 | 不应替代 |
|---|---|---|
| 00 章节定位与史实边界 | 何时、何地、哪些史实可亲历、哪些不可越界 | 人物戏和台词 |
| 01 主线大纲 | 一生如何被历史压力推动，八幕怎样构成完整人生 | 十条职业详细剧情 |
| 02 人物关系表 | 人物是谁、想要什么、怎样独立行动与变化 | 单纯 NPC 名单 |
| 03 职业线嵌入表 | 每个社会位置如何拥有独立故事、权限、责任与结局 | 数值职业树 |
| 04 因果节点表 | 选择怎样进入事实、记录、人物和后世 | 善恶值 |
| 05 记忆碎片表 | 本章身份谜题推进哪一层，何时触发，怎样影响现实 | 超能力和预知 |
| 06 故事剧本 | 场景、行动、冲突、对白目标和演出需求 | 只有梗概没有戏 |
| 07 衔接过渡文 | 如何读取所有合法分支并拼成完整时代变迁 | 固定结局旁白 |

## 3. 每章统一结构

每章原则上使用八幕：

```text
ACT01 苏醒与本世家庭
ACT02 共同成长与第一次时代压力
ACT03 主动选择社会位置
ACT04 职业承诺与第一次独立代价
ACT05 私人关系和时代矛盾同时升级
ACT06 职业线独立高潮
ACT07 全职业从不同位置进入共同历史危机
ACT08 晚年、档案、未尽之事与跨章交接
```

ACT01—ACT03 约占首轮内容 35%，以共享主线为主。

ACT04—ACT06 约占 35%，每条职业形成可独立概括的故事。

ACT07—ACT08 约占 30%，共享历史事件，但不同职业拥有不同任务、不可替代证据、人物失去与交接材料。

推荐内容比例：

```text
共享场景：55%—65%
职业独有场景：25%—35%
稀有人物与因果回收：10%
```

职业独立不等于十套互不相干的游戏。独立指每条线都有自己的欲望、对手、关系核心、三次升级、专属高潮和结局判断。

## 4. 职业独立主线验收

每条职业线必须填写：

| 字段 | 要求 |
|---|---|
| `route_promise` | 玩家选择这条线后会经历什么独特人生 |
| `route_desire` | 本世真正想得到什么，不得只是“做好职业” |
| `route_fear` | 最害怕失去什么 |
| `route_blind_spot` | 人物性格造成的判断盲点 |
| `mentor_or_peer` | 一名能理解玩家、也会反对玩家的人 |
| `human_opponent` | 有合理利益和私人情感的对手 |
| `institutional_pressure` | 不可被击败的制度或时代压力 |
| `three_escalations` | ACT04、ACT05、ACT06 三次不可重复的升级 |
| `route_climax` | 只有该职业能够完成的行动 |
| `irreversible_cost` | 无法通过读档思维“全都要”的损失 |
| `unique_evidence` | 进入本章档案的独有材料 |
| `convergence_role` | ACT07 共同危机中的不可替代责任 |
| `route_ending` | 成为、离开、被逐、改行、牺牲或传承等合法结局 |
| `next_chapter_trace` | 下一章能够现实回收的载体 |

如果把职业名称替换后故事仍成立，说明职业差异不够。

如果高潮只是在同一场战斗中使用不同技能，说明项目已经偏离历史叙事人生 RPG。

## 5. 人物立体度规范

### 5.1 核心人物九字段

每名核心人物必须拥有：

```text
surface_identity       公开身份
private_desire         私人欲望
public_claim           对外宣称的原则
fear                   最深恐惧
blind_spot             认识盲点
tenderness             不用于推进剧情的柔软处
material_interest      现实利益
line_never_cross       自认为绝不跨越的线
line_actually_crossed  最终可能跨越的线
```

### 5.2 人物不是玩家附属物

核心人物必须：

- 在玩家缺席时采取至少一次行动。
- 至少一次拒绝玩家。
- 有一段不围绕苏醒者存在的关系。
- 可能因自己的判断成功或失败。
- 不因好感度高就放弃根本利益。
- 在不同职业线中保持同一人格，只改变彼此看见的侧面。

### 5.3 人物命运

人物命运至少包含：

```text
fixed_action         无论玩家如何都会做的事
preventable_loss     玩家可以避免或转移的损失
irreversible_change  一定发生、但表现可变的改变
survival_variants    生还、死亡、失踪、迁徙、改名、决裂
testimony_variants   此人留下的事实版本
carrier_variants     此人可能带走的跨章载体
```

“生还”不是自动好结局，“死亡”也不能成为制造深刻感的廉价按钮。

## 6. 故事剧本格式

### 6.1 场景头

```text
scene_id:
act:
route:
time:
location:
present_characters:
historical_pressure:
player_goal:
character_goals:
entry_conditions:
exit_states:
assets:
```

### 6.2 场景正文

每场按以下顺序：

1. **视觉开场**：一个可被画面和声音表现的动作。
2. **现实目标**：人物必须在场景结束前完成或失去什么。
3. **冲突升级**：至少两个人的合理目标不能同时满足。
4. **玩家行动**：选择具体做法，而不是抽象立场。
5. **人物反应**：由性格、利益和共同债决定，不由好感度单独决定。
6. **状态落点**：明确写入事实、关系、资源、记录或因果。
7. **余波钩子**：下一场为什么必然发生。

### 6.3 对白标准

- 台词必须来自人物此刻的目标，不能替作者讲总纲。
- 同一观点由不同身份说出时，词汇、比喻和关心对象必须不同。
- 重要选择前不给“明显正确答案”的语气提示。
- 历史称谓按本章史实边界处理。
- 允许沉默、误解、谎言和说一半。
- 每名核心人物建立三项语言特征，禁止所有人都说宏大金句。

## 7. 选择设计

每个主选择至少改变下列两项：

```text
事实结果
人物关系
资源或伤病
制度权限
官档版本
私人记录
口述版本
因果载体
后续责任
```

选项文案描述玩家要做的动作，不替玩家规定情绪：

```text
合格：把缺粮户写进今夜补录名单
不合格：选择仁慈
```

延迟结果不得全部隐藏。玩家当场至少要知道：

- 自己做了什么。
- 谁立即承担风险。
- 哪项结果仍不确定。

## 8. 分支收敛规范

### 8.1 收敛不是归零

所有职业会进入同一历史危机，但必须从不同现实位置进入：

```text
同一危机
├─ 农人：粮、田、家户与逃生
├─ 吏官：名册、命令与删改
├─ 医者：伤病、隔离与救治顺序
├─ 工匠：道路、器物、工程与破坏
├─ 商贾：运输、价格、债与情报
├─ 乐人：口述、情绪、传播与禁令
├─ 军人：命令、同袍、平民与战场责任
├─ 谋士：信息、结盟、代价分配与误判
├─ 仕官：政策、合法性、执行链与公开责任
└─ 隐士：退出权力后的地方知识、庇护与见证
```

ACT07 结束时，历史结果相同，人间结果不同。

### 8.2 章节交接包

每章固定输出：

```text
historical_result
route_result
core_character_fates
truth_state
official_record
private_record
oral_version
primary_carrier
secondary_traces
institutional_legacy
memory_cue
unanswered_question
mandatory_callbacks
```

### 8.3 过渡文由模块拼成

过渡文不得只写一篇固定散文。文件必须包含：

1. 固定历史桥段。
2. 十条职业路线各一段合法插入块。
3. 核心人物命运组合表。
4. 主要载体的变形块。
5. 记录冲突块。
6. 下一章固定开场压力。

运行时结构：

```text
固定本世晚年
→ 主职业结局块
→ 两至三名核心人物命运块
→ 事实 / 官档 / 私录冲突块
→ 载体跨年变化
→ 历史时间桥
→ 下一世苏醒
→ 强制现实事件
```

过渡文必须能够读到所有合法分支，但一次游玩只选择与当前存档相符的块。

## 9. 因果节点规范

### 9.1 节点状态

```text
DORMANT
PLANTED
DEVELOPING
RESOLVED_LOCAL
CARRIED
RETURNED
TRANSFORMED
CLOSED
BROKEN_WITH_TRACE
```

### 9.2 节点最低字段

```text
id
name
priority
first_scene
route_scope
truth_state
player_knowledge
official_record
private_record
oral_version
cost_bearer
immediate_result
chapter_result
carrier
next_callback
fallback_if_lost
closure_condition
```

P1 节点必须进入共享主线，不能因职业选择而完全错过。

职业专属节点必须在下一章拥有现实作用，不得只出现一句彩蛋。

## 10. 记忆规范

每章身份谜题只推进一层：

| 章 | 记忆要推翻的错误解释 |
|---|---|
| CH01 | 这只是普通梦境 |
| CH02 | 我是某一家族祖先的轮回 |
| CH03 | 我只属于一个故乡和一种共同体 |
| CH04 | 我只记得盛世中心或英雄经验 |
| CH05 | 我是某位文明精英的转世 |
| CH06 | 我记忆中的改变来自少数先知 |
| CH07 | 我是站在人民之外替他们发言的人 |
| 终章 | 仍存在一个等待揭晓的私人真名 |

记忆只改变观察、询问、措辞和关系风险，不提供：

- 战斗加成。
- 准确预言。
- 现代技术答案。
- 历史事件百科。
- 唯一正确选项。

## 11. 史实边界

每章必须先写 `00_章节定位与史实边界`，至少列出：

- 时间和地点。
- 当时存在与不存在的制度。
- 身份、称谓、交通、货币、文书、衣食住行。
- 普通人能够知道什么。
- 本章会使用的史实争议。
- 为戏剧压缩了什么。
- 明确禁止的时代错置。

史实服务人物行动边界，不用来堆百科旁白。

## 12. 建议内容量

单章 V0.1 预制作包建议：

| 内容 | 数量 |
|---|---|
| 八幕共享主线 | 8 幕 |
| 核心人物 | 8—12 名 |
| 支撑人物 | 8—16 名 |
| 职业路线 | 10 条 |
| 每职业独有关键场景 | 3—5 场 |
| 共享关键场景 | 16—24 场 |
| 因果节点 | 25—40 个 |
| 记忆碎片 | 10—18 个 |
| 主要结局状态 | 每职业 3—5 种 |
| 过渡插入块 | 职业、人物、载体和记录四类 |

V0.1 的“故事剧本”是可直接继续写正式对白的分场剧本，不要求第一版就把所有对白写到最终字数。关键选择、人物行动、场景目标和状态落点不得留空。

## 13. 完成顺序

每章严格按：

```text
史实边界
→ 主线大纲
→ 人物关系
→ 职业独立主线
→ 因果节点
→ 记忆碎片
→ 分场故事剧本
→ 动态衔接过渡文
→ 全路线审计
```

后写文件发现上游逻辑问题时，必须回改上游，不能在剧本里临时打补丁。

## 14. 全路线验收

- [ ] 每条职业线可以用三句话讲出独有故事。
- [ ] 每条职业线有一名关系核心和一名合理对手。
- [ ] 每条职业线有只有该身份能完成的高潮行动。
- [ ] 所有职业进入同一历史危机，但责任不同。
- [ ] 核心人物在玩家缺席时仍会行动。
- [ ] 重要选择至少改变两类状态。
- [ ] P1 因果不因职业分流丢失。
- [ ] 记忆没有提供正确答案和超时代能力。
- [ ] 过渡文能读取全部职业、人物、载体和记录分支。
- [ ] 下一章开场能从任一合法交接包开始并快速汇流。
