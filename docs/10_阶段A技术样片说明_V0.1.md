# 《山河无名》阶段 A 技术样片说明 V0.1

> 样片：第一章 ACT01《雨后流民》  
> 入口：`http://127.0.0.1:4173/`  
> 目标：用 10—15 分钟证明内容、状态、档案与存档边界，而非提前制作最终美术。

## 1. 已实现

- `scene`、`character`、`cause`、`record`、`save` JSON 数据契约。
- 平台无关的事件驱动故事运行时。
- ACT01《雨后流民》10 个节点和 324 条完整路线。
- 人物信任、共同债与裂痕。
- 暮色、粮、体力三类有限资源。
- 事实、官档、私录、口述四层并列。
- 裂钟、半名残简、亡国旧曲与第一份流民名册四项因果。
- 手动存档、自动存档、JSON 导入导出与事件回放。
- 断路、重复节点、无效人物 / 因果引用与不可达节点检查。
- 桌面三栏界面和 390px 窄屏布局。

## 2. 架构边界

```text
content/                 编剧可修改的 JSON 内容
packages/story-core/     不依赖网页界面的运行时
apps/web/                浏览器渲染和交互适配
tools/route-auditor/     内容与路线自动校验
prototype/               V4 历史实验，不继续堆叠
```

界面不得直接修改故事状态。一次选择依次生成：

```text
choice.select
→ fact / resource / relationship / record / cause / memory 事件
→ scene.enter
→ 新状态
```

存档同时保存状态快照和事件日志。读取时从初始状态重新回放事件，并与快照比较；不一致的存档会被拒绝。

## 3. 当前内容

玩家在雨后洛水渡口面对三组连续冲突：

1. 第一反应：拾简、救孩子或询问众人。
2. 核心责任：救治、抢救记录或共同点名。
3. 半名残简：交给韩宁、共同辨认或暂时藏起。
4. 亡国旧曲：唱姓名、保留沉默或恢复国名。
5. 名册去向：官档、暗册、旧曲或分散保管。

每种做法都能解决部分问题，也会产生不可撤销的代价。

## 7. 评审重点

请优先判断：

1. 文字阅读节奏是否舒服。
2. 三层记录差异是否容易理解。
3. 选择是否真的令人犹豫，而不是猜“正确答案”。
4. 左侧人物 / 资源与右侧档案是否信息过多。
5. 这种视觉质感是否适合扩展为 ACT01—ACT02 核心原型。
