# 《山河无名》阶段 B 网页核心原型说明 V0.1

> 内容：第一章 ACT01《雨后流民》—ACT02《旧礼无声》
>
> 入口：`http://127.0.0.1:4173/`
>
> 目标：验证 30—45 分钟连续叙事、多场景内容生产、分层档案、记忆反馈和跨幕存档。

## 1. 本阶段结果

- ACT01—ACT02 共 2 个场景文件、21 个内容节点。
- 预计首轮阅读与选择时长约 32 分钟。
- 34,992 条完整路线全部抵达 ACT02 结尾。
- 单路线产生 93—103 条可回放事件、8—10 份分层记录。
- 34,992 份事件回放式存档与状态快照一致。
- 桌面与 390px 窄屏浏览器验证通过。

首轮外部测试仍需由真实玩家完成，因此路线图只将前三项工程目标标记完成。

## 2. ACT01 到 ACT02 的连续因果

ACT01 留下：

```text
第一份流民名册
半名残简
裂钟记忆
官档 / 私录 / 口述的不同保管方式
季伯、禾安、韩宁、柳娘的关系状态
```

ACT02 不清空这些结果。四年后，第一份流民名册与旧仓放粮发生现实碰撞：

```text
依旧礼请恤
├─ 保留公开名分与拒绝记录
└─ 由误期播种者承担等待

接受暂编新籍
├─ 当日开仓、获得粮种
└─ 田、役、清查和连带责任同时成立

商队私下调粮
├─ 二十三户及时播种
└─ 商队信用、粮债和隐匿风险转入私人
```

三路都会汇入“被划去的人”，但不会归零：结局会分别显示谁得粮、谁误期、谁背债，以及这些事实进入哪一层记录。

## 3. 新增工程边界

### 3.1 多场景内容包

章节清单通过 `sceneFiles` 顺序加载多个 JSON 场景。运行器将节点建立为跨文件图，选择可以安全指向下一场景。

校验器新增：

- 重复场景、节点、选择、人物、因果和记忆 ID 检查。
- 场景起点归属检查。
- 跨文件缺失节点检查。
- 记忆引用和记忆关联因果检查。
- 官档、私录、口述三层存在性检查。
- 从章节起点到结局的可达性检查。

### 3.2 记忆数据

新增独立 `memory` 契约与记忆数据文件。界面只展示玩家可感知内容和现实作用，不展示底层来源或身份答案。

当前包含：

- `MEM-CH01-001 裂钟落水`
- `MEM-CH01-002 湿简与无脸之手`
- `MEM-CH01-003 空白木片`
- `MEM-CH01-004 仓门后的呼吸`

前三项为必选并拥有兜底入口；第四项只在玩家主动追问未入籍资格时触发。记忆不增加技能，不预告未来。

### 3.3 存档与事件

存档继续从章节起点回放全部事件，并新增检查：

- 内容版本与运行时版本一致。
- 事件日志非空。
- 事件序号连续。
- 第一条事件必须进入当前章节起点。
- 回放失败返回可理解的错误，不让损坏存档直接中断界面。

### 3.4 档案界面第一版

档案页现在同时展示：

- 已确认事实数量。
- 官档、私录、口述记录数量与来源。
- 完整度和暴露风险。
- 可信状态与敏感等级。
- 当前最重要的版本冲突。

人物关系不再只显示合计值，同时显示信任、共同债与裂痕。

## 4. 内容验收

ACT02 四次主选择分别回答：

1. 用哪种办法取得旧仓之粮。
2. 如何回应空白木片记忆。
3. 被划去姓名的理由写在哪里。
4. 谁替从未入册的一户承担证明责任。

每个主选择至少改变事实、关系、资源、记录、因果或后续责任中的两项。选项不使用善恶标签，也没有同时保住粮、身份、隐私和公开责任的全得路线。

## 6. 浏览器验收

- ACT01 结尾可连续进入 ACT02，人物、事实、记录和因果不清空。
- 跨幕时农时、粮与体力按 ACT02 场景重新初始化。
- ACT02 中途手动保存，继续两次选择后读取，可准确回到“空白木片”。
- 记忆页能区分已触发、必选未触发与可选未触发。
- 主动追问路线能触发“仓门后的呼吸”，其他路线通过针线支出找到同一现实人物。
- ACT02 结局同时显示赈粮方式和漏记户安置结果。
- 390px 窄屏无横向溢出。
- 浏览器控制台无警告或错误。

## 8. 首轮外部测试问题

请优先记录：

1. ACT01 到 ACT02 的四年跳转是否自然。
2. 旧礼、新籍和私粮三条路是否都让人犹豫。
3. 右侧档案是否帮助理解，还是打断阅读。
4. “空白木片”是否像现实问题的回声，而不是超能力提示。
5. ACT02 的四次主选择是否过密或过慢。
6. 结尾是否足以产生继续追查韩宁父亲旧册的兴趣。
