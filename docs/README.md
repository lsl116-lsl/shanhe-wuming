# 《山河无名》文档总入口

> 用途：让新成员先读懂项目，再按任务读取必要资料，避免被旧版本、历史原型和未冻结草案带偏。

## 1. 第一次进入项目

依次阅读：

1. [项目概述 V1.0](00_核心文档/01_项目概述_V1.0.md)
2. [项目框架 V1.0](00_核心文档/02_项目框架_V1.0.md)
3. [全篇故事走向 V1.0](00_核心文档/03_全篇故事走向_V1.0.md)
4. [章节包索引](chapters/README.md)

前三份文件是当前项目的最高层口径，分别回答：

```text
这是什么项目，真正想表达什么？
章节、视角、因果、玩法和制作怎样协同？
序章到终章究竟发生什么，认识怎样逐章变化？
```

## 2. 文档权威顺序

发生冲突时按以下顺序判断：

```text
docs/00_核心文档/ 三份 V1.0 核心文档
→ 根目录 AGENTS.md
→ 目标章节 README 与当前主线大纲
→ 人物、因果、记忆、职业和制作规范
→ 旧版总框架、历史原型与实验说明
```

`docs/00_项目总框架_V0.5.md` 保留详细系统字段和上游材料，但不再高于 V1.0 核心文档。

## 3. 当前已确定口径

```text
产品：章节式 2D 历史叙事人生 RPG / AVG。
长线：序章 + 七章 + 终章。
核心：通过不同社会位置理解同一段历史，不是寻找主角真名。
每章：一段有姓名、家庭、关系和晚年的完整人生。
玩家：不能改写宏观史实，能改变具体人物、执行方式和历史材料。
第一章：八职业视角 + 乡土地基 + 隐退倾向。
当前制作：Godot 原生 Windows 序章《雨来之前》垂直切片。
```

“无名”指未被主流历史充分呈现的普通人，不指主角没有名字。裂钟、残梦和苏醒只连接时代与视角，不回答血统、真身或天命。

## 4. 文档分层

### A. 核心口径

目录：`docs/00_核心文档/`

所有团队成员都要阅读。只有项目层决策可以修改。

### B. 项目支持规范

```text
docs/01_跨朝代因果总表_V0.1.md
docs/08_项目落地方案_V0.1.md
docs/09_章节包制作规范_V0.1.md
docs/13_人物塑造规则_V0.1.md
docs/14_可移动探索与眼前代价系统_V0.1.md
```

这些文件分别服务跨章因果、制作路线、章节包结构、人物写作和互动设计。它们不能自行改变项目主题。

### C. 章节包

目录：`docs/chapters/`

每章包含史实边界、主线、人物、职业视角、因果、记忆、故事剧本和过渡文。当前序章与第一章最成熟；第二章以后主要是故事总纲与概念验证，仍允许调整。

### D. 制作与实现

```text
docs/production/
apps/godot/
tools/
```

制作规格和代码负责把已确定的故事做出来，不得反向把技术方便改写成故事核心。

### E. 历史原型与旧版本

旧网页原型、阶段 A / B 说明、旧总框架和早期职业模板只用于追溯决策或复用技术，不是当前需求来源。

## 7. 当前冻结与未冻结

### 已冻结

- 多视角认清历史是长线核心；
- 不寻找主角真名或天命身份；
- 一章一生，宏观史实不由玩家改写；
- 序章和第一章主线边界；
- 第一章八职业、乡土地基和隐退倾向；
- 禾安、梁成、长平、旧粥碗与《无名录》的共用收束；
- 当前先完成序章 Godot Demo。

### 未冻结

- 第二章以后每章最终保留多少视角线；
- 后续章节全部关键 NPC、场景数量和玩法密度；
- 苏醒机制最终解释到什么程度；
- 终章精确年份与最终镜头；
- 正式美术资产和配音阵容。

## 8. 项目级禁忌

```text
不要把主线改回寻找真名、前世身份或血统。
不要把职业写成互不相关的换皮副本。
不要让残梦直接提供标准答案。
不要用善恶值代替人物与历史因果。
不要让角色为了主题说故作高深的话。
不要把普通人写成只有受苦功能的背景。
不要让技术样片或占位美术反向决定最终审美和故事。
不要把后续章节旧十职业清单当成已冻结制作范围。
```
